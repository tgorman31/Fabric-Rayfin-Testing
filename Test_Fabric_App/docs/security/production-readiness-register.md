# Production-readiness register

## Purpose

This register translates the application’s open security and operational questions into evidence and decisions that can be reviewed with internal IT, security, identity and platform stakeholders. It is intended to evolve as evidence is gathered.

It is not a certification, approval, threat model or declaration that the application is production-ready.

## Status vocabulary

- **Open** — the question remains unanswered or evidence/decision is missing.
- **Evidence available** — current repository or explicitly linked evidence supports the narrow statement; this does not imply organisational approval or production configuration.
- **Accepted risk** — an authorised organisational risk decision exists; no such decisions are evidenced here.
- **Not applicable** — an authorised decision records that the item does not apply.

Do not mark a row complete merely because a source file exists. Code can prove that a control is implemented in the application; it cannot by itself prove organisational approval, production configuration, platform guarantees, operational ownership, restore testing or accreditation.

## How to use this register

Update a row only when evidence or an authorised organisational decision exists. Link the evidence, record the date and preserve the distinction between a repository code control and a production/platform assurance. Open questions should remain visible rather than being converted to green status by inference.
